API

API

Application Programming Interface
Plain English
A defined way for two systems to communicate.
Think of it like
A waiter carrying your request to the kitchen and bringing the response back.
See how it works
Mobile App
→
API
→
Service
→
Database
You'll hear this at work
“We'll expose an API for customer details.”
Translation: another system will have an agreed way to request customer information.
Why should I care?
APIs create dependencies between systems. A small contract change can affect several consumers.
If you're a BA, ask
  • What triggers the request?
  • What data goes in and comes back?
  • What happens when it fails?
  • Who is allowed to call it?
Don't confuse
API
Lets systems communicate
Database
Stores data

Kafka

Event streaming / messaging
Plain English
Kafka lets systems publish events that other systems can consume.
Think of it like
A shared noticeboard: one team posts an event; interested teams pick it up.

You'll hear this at work
“Publish the order event to Kafka.”
Translation: publish an event instead of directly calling every downstream system.
Why should I care?
Events raise questions about timing, duplicates, failures and downstream consumers.
BA lens
  • What creates the event?
  • What data does it contain?

CI/CD

Continuous Integration / Continuous Deployment
Plain English
Automation that checks, packages and delivers code as it changes.
Think of it like
A conveyor belt that checks each change before moving it toward release.
See how it works
Code
→
Build
→
Tests
→
Deploy
You'll hear this at work
“The CI/CD pipeline failed.”
Translation: something in the automated build, test or delivery process did not complete.
Why should I care?
A finished requirement does not mean the change successfully reached an environment.
BA lens
  • Which stage failed?
  • Which environment?
  • Did automated tests pass?
  • Was the change actually deployed?
Don't confuse
Deploy
Put software into an environment
Release
Make it available to users
